5 — Risk Review
Correctness

Concern: R2 endpoint URL construction assumes R2_ACCOUNT_ID and R2_BUCKET_NAME env vars are set correctly. If missing, the S3Client uses empty strings and requests fail.

Verdict: Matches v1 — same risk with AWS env vars. Acceptable.

Tests

Zero tests added. The v1 controller also has no tests. This follows the existing pattern (no test infrastructure for controller-level logic in this project).

Verdict: No regression — but testing R2 integration would catch env var issues early.

API Compatibility

8 new endpoints under /api/v2/merchandise/*. No existing endpoints modified. v1 routes remain fully functional.

Verdict: Zero breaking changes. Routes need registration in index.ts to go live.

Security / Privacy

Known risk: any types in MulterS3.File[] callback parameters (cb: any). No input sanitization beyond what v1 does. Same auth middleware chain as v1.

Verdict: Same baseline as v1. No regression.

Performance

Image deletion in updateMerchandiseV2Controller uses Promise.all — same as v1. Multi-write update touches 4 collections without transaction — same risk as v1.

Verdict: Acceptable for current scale.

Maintainability

Code exactly mirrors v1 patterns: raw try/catch, mixed response formats, duplicated R2 clients. A deliberate choice to avoid abstractions. ponytail: shortcuts are noted in the implementation.

Verdict: Consistent with codebase. Easy for anyone who understands v1.

Hidden Coupling

Env Var Coupling

4 new required env vars (R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET_NAME). Without them, R2 operations fail silently (empty string credentials → S3Client throws at runtime).

R2 Endpoint URL

Image deletion in updateMerchandiseV2Controller strips the R2 endpoint prefix to get object keys. If the R2 URL format differs (custom domain vs r2.dev), the key extraction breaks.

Route Registration

Route file is created but not registered in index.ts. Two manual lines needed: import + app.use("/api/v2/merchandise", ...). Until then, endpoints return 404.

No Existing Code Impact

Zero edits to existing files means zero risk of regression in v1 or other v2 features. The IOrdersItems fix is additive (only adds properties, never removes).

Migration / Release Note

To activate: (1) add 4 R2 env vars, (2) register route in index.ts, (3) deploy. Frontend changes for the admin panel (to use v2 endpoints) are a separate scope not included here.
